### Функциональные требования

|:-----:|:---------------------------------|:------------|:-------------|
| UC-01 | Менеджер внутреннего кол-центра | Консультация клиента по ставкам | При звонке клиента менеджер видит актуальные ставки по депозитам в системе кол-центра |
| UC-02 | Менеджер партнёрского кол-центра | Консультация клиента по ставкам | При звонке клиента менеджер партнёрского кол-центра имеет доступ к актуальным ставкам (через файл) |

### Нефункциональные требования

| № | Требование |
|:-----:|:---------------|
| NFR-01 | Ставки должны обновляться в кол-центре не позднее 15 минут после изменения в АБС |
| NFR-02 | Ставки для партнёрского кол-центра должны доставляться в виде файлов через SFTP (API невозможен) |
| NFR-03 | Формат файла для партнёра должен быть согласован и стабилен (CSV/XML) |
| NFR-04 | Процесс передачи ставок не должен создавать дополнительную нагрузку на АБС |
| NFR-05 | Аутентификация и авторизация доступа к ставкам (как для API, так и для SFTP) |
| NFR-06 | Аудит изменений ставок и фактов их передачи вовне |
| NFR-07 | Отказоустойчивость: при сбое передачи файла должна быть реализована система повторных попыток |
| NFR-08 | Сохранение истории ставок для возможности отката при ошибках |

### Обоснование архитектурных решений

1. Создание REST API для доступа к ставкам
    - Обеспечивает быстрый и стандартизированный доступ для внутренних систем
    - Использует Java (есть экспертиза в команде АБС)
    - Позволяет легко добавлять новых потребителей в будущем

2. SFTP-экспорт для партнёра
    - Соответствует требованиям партнёра (только файлы, API невозможен)
    - Обеспечивает безопасную передачу данных
    - Механизм повторных попыток гарантирует доставку

3. Кэширование ставок в Redis
    - Снижает нагрузку на АБС (не нужно обрабатывать каждый запрос оператора)
    - Обеспечивает быстрое отображение ставок в интерфейсе
    - Автоматическое обновление при изменениях

4. Аудит изменений и экспорта
    - Соответствие регуляторным требованиям
    - Возможность отследить источник ошибок при расхождениях
    - История для отката при необходимости

### Альтернативы

| Альтернатива | Описание | Причина отклонения |
|:-----------------|:-------------|:------------------------|
| Прямой доступ партнёра к API АБС | Предоставление партнёру REST API для получения ставок | API невозможен по условию задачи; партнёр работает только с файлами |
| Ручная отправка файлов | Менеджер бэк-офиса вручную выгружает файл и отправляет партнёру по email | Высокий риск ошибок, задержек, не соответствует NFR-01 (15 минут) |
| Единая база ставок в отдельной системе | Выделение ставок в отдельный сервис с API для всех потребителей | Требует значительных доработок, выходит за рамки MVP |
| Использование общих файловых ресурсов (NFS) | Организация общего сетевого диска для партнёра | Требует сложной настройки безопасности, не соответствует требованиям партнёра |
| Публикация ставок на сайте | Размещение ставок в открытом доступе на сайте банка | Ставки могут быть персонализированными и не предназначены для публичного раскрытия |

### Недостатки, ограничения, риски

| Риск | Вероятность | Влияние | Меры митигации |
|:---------|:---------------:|:-----------:|:--------------------|
| Расхождение ставок в разных системах | Средняя | Высокое | Использование механизма версионирования, мониторинг расхождений, сверка каждые 30 минут |
| Сбой SFTP-доставки | Низкая | Среднее | Механизм повторных попыток (3 попытки с интервалом 5 минут), алерты при сбоях |
| Устаревание формата файла для партнёра | Низкая | Низкое | Согласование формата, версионирование спецификации, уведомление за 30 дней до изменений |
| Дополнительная нагрузка на АБС при опросах API | Средняя | Среднее | Кэширование ставок в Redis, ограничение частоты запросов (max 1 раз в минуту) |
| Несанкционированный доступ к ставкам | Низкая | Критическое | Аутентификация по API-ключам, авторизация по ролям, аудит доступа, сертификаты для SFTP |
| Задержки обновления > 15 минут | Средняя | Среднее | Мониторинг времени доставки, оптимизация процессов, алерты при превышении 10 минут |
| Некорректные данные в файле для партнёра | Низкая | Среднее | Валидация перед отправкой, логирование ошибок, уведомление администратора |
| Отсутствие обратной связи от партнёра | Средняя | Низкое | Внедрение механизма подтверждения получения файла (лог-файл) |

### Ограничения решения

1. Однонаправленность – решение обеспечивает только передачу ставок от банка к партнёру, обратная связь не предусмотрена
2. Задержка доставки – при использовании SFTP возможна задержка до 5-10 минут (в пределах NFR-01)
3. Отсутствие персонализации – партнёрский кол-центр получает только базовые ставки, без персонализации
4. Ручное согласование формата – любые изменения формата файла требуют согласования с партнёром
5. Зависимость от SFTP-сервера – решение требует поддержки и мониторинга отдельного SFTP-сервера
