## Таблица требований по методике FURPS+

---

### Проект: Цифровая трансформация банка «Стандарт» (MVP депозитов и кредитов)
#### Версия: 1.0
#### Дата: 11.03.2026

| Код | Требования | Комментарий |
|:---:|------------|-------------|
| **F** | **Функциональные (Functionality)** | |
| F1 | Сайт: отображение списка доступных депозитов с актуальными ставками. | Ставки должны подтягиваться из нового источника (не из XLS). |
| F2 | Сайт: возможность подачи заявки на депозит для нового клиента (ФИО + телефон). | |
| F3 | Сайт: отображение предложения по кредиту с базовой ставкой. | |
| F4 | Сайт: возможность подачи заявки на кредит с указанием ФИО, телефона и паспортных данных. | При наличии паспортных данных – немедленное обращение к системе скоринга. |
| F5 | Интернет-банк: отображение персонализированных ставок по депозитам. | Ставки зависят от истории клиента и текущих рисков. |
| F6 | Интернет-банк: возможность подачи заявки на депозит с выбором счета и суммы. | |
| F7 | Интернет-банк: отображение предодобренных предложений по кредиту. | |
| F8 | Интернет-банк: подача заявки на кредит (в т.ч. по предодобренному предложению). | |
| F9 | Подтверждение операций в интернет-банке с помощью СМС-кода. | |
| F10 | СМС-информирование клиента об изменении статуса заявки (депозит/кредит). | |
| F11 | Интеграция сайта и интернет-банка с АБС для создания заявок (избегая прямой нагрузки на БД АБС). | Критическое требование – АБС перегружена. |
| F12 | Интеграция с системой кол-центра для передачи заявок с сайта. | Менеджер кол-центра видит заявку и может предложить особые условия. |
| F13 | Интеграция с Кредитным конвейером для передачи заявок на кредит. | |
| F14 | Интеграция с системой скоринга для оценки новых клиентов (по паспортным данным и БКИ). | |
| F15 | Интеграция с АБС для сотрудников отделений: возможность видеть заявки, созданные клиентом онлайн. | Чтобы не создавать дубликаты. |
| F16 | Возможность сотрудникам бэк-офиса управлять ставками по депозитам через АБС (а не через XLS). | Замена Excel-файлов на функционал в АБС. |
| **U** | **Удобство использования (Usability)** | |
| U1 | Соответствие единой дизайн-системе банка (фирменные цвета, брендированные элементы). | |
| U2 | Интуитивно понятный интерфейс подачи заявок (не более 3 шагов). | |
| U3 | Адаптивный дизайн для мобильных устройств (сайт и интернет-банк). | |
| U4 | Понятные уведомления о статусе заявки (для клиента). | |
| **R** | **Надёжность (Reliability)** | |
| R1 | Доступность интернет-банка и сайта – 99.9% (24/7). | Сейчас требования не выполняются, необходима модернизация. |
| R2 | Отказоустойчивость: автоматическое переключение на резервный ЦОД при сбое основного. | |
| R3 | Сохранность данных заявок при сбоях (acknowledgment). | |
| R4 | Обработка ошибок интеграций (retry, fallback) без потери данных. | |
| R5 | Целостность данных при передаче заявки между системами. | |
| **P** | **Производительность (Performance)** | |
| P1 | Время отклика интерфейсов (загрузка страниц, отображение ставок) – не более 300 мс. | Сейчас некоторые справочники грузятся >1с. |
| P2 | Время обработки заявки на депозит (до СМС-подтверждения) – не более 2 секунд. | |
| P3 | Время получения скоринга для новой заявки с сайта – не более 5 секунд. | |
| P4 | Способность выдержать пиковые нагрузки (рекламные кампании, начало месяца). | |
| P5 | Горизонтальное масштабирование интернет-банка и новых сервисов. | АБС масштабируется только вертикально – прямая интеграция недопустима. |
| P6 | Отсутствие прямой нагрузки на БД АБС со стороны онлайн-каналов. | |
| **S** | **Поддерживаемость (Supportability)** | |
| S1 | Модульность: выделение функционала депозитов/кредитов в отдельные микросервисы (в перспективе). | Для снижения связанности и возможности независимого развертывания. |
| S2 | Использование технологий, уже присутствующих в банке (MS SQL, Oracle, Java, Python). | |
| S3 | При необходимости новых технологий – совместимость с существующими платформами и наличие экспертизы внутри банка. | |
| S4 | Документирование API новых сервисов для дальнейшего расширения. | |
| S5 | Использование Kafka для асинхронного обмена (в перспективе). | Текущая версия интернет-банка несовместима, потребуется модернизация. |
| S6 | Возможность независимого развертывания компонентов (CI/CD). | |
| S7 | Логирование и мониторинг всех операций. | |
| **+R** | **+ Ограничения (Restrictions)** | |
| +R1 | Шифрование трафика (HTTPS/TLS) для всех внешних каналов (сайт, интернет-банк). | |
| +R2 | Защита персональных данных (ФИО, телефон, паспорт) при передаче и хранении. | Соответствие 152-ФЗ. |
| +R3 | Разделение доступа: сотрудники депозитов и кредитов не имеют доступа к данным друг друга. | |
| +R4 | Аудит всех действий с заявками (кто, когда, что изменил). | |
| +R5 | Ограничение на доработки ядра АБС и системы кол-центра (минимизация изменений силами подрядчика). | |
| +R6 | Кредитный конвейер и система скоринга не должны перегружаться дополнительными предрасчетами. | |
| +R7 | Соответствие законодательству об идентификации клиентов (личная явка для новых клиентов). | |
